# 產品需求文檔 (PRD)

# Card ERP - OMO 收藏卡交易平台

**版本**: 1.0
**最後更新**: 2026-01-24
**負責人**: Product Team

---

## 一、產品概述

### 1.1 產品願景

打造一個線上線下整合的收藏卡交易平台，支援實體店面掃碼結帳、多賣家寄賣、線上競標等功能，為收藏家與店家提供完整的 OMO 交易體驗。

### 1.2 目標市場

- **主要商品**: 裸卡（未鑑定）、鑑定卡（PSA/ARS/BGS）、周邊商品（保護殼等）
- **商品類別**: 海賊王、寶可夢、遊戲王、棒球卡等收藏卡
- **目標用戶**:
  - 收藏家（買家）
  - 實體店面客戶
  - 第三方寄賣賣家

### 1.3 核心價值

- **線上線下庫存同步**: 實體店面商品同步上架線上，賣出立即下架
- **多元交易方式**: 直購、競標、面交等多種選擇
- **寄賣平台**: 支援第三方賣家寄賣，自動抽成結算
- **高效管理**: QR Code 快速結帳、自動報表生成

## 二、商業模式

### 2.1 營收來源

#### 自營商品

- 實體店面銷售（現場交易、掃碼結帳）
- 線上商城銷售（直購 + 競標）
- 全部收入歸店家

#### 寄賣商品

- **上架費**: 實體 / 線上上架費用（依賣家等級）
- **交易抽成**: 商品售出後抽成比例（依賣家等級）

### 2.2 賣家等級制度

| 等級     | 升級條件                 | 線上上架費 | 實體上架費 | 交易抽成 |
| -------- | ------------------------ | ---------- | ---------- | -------- |
| **銅牌** | 註冊即可                 | TBD        | TBD        | 15%      |
| **銀牌** | 銷售額 5 萬 OR 付費會員  | TBD        | TBD        | 12%      |
| **金牌** | 銷售額 20 萬 OR 高級會員 | TBD        | TBD        | 8%       |

**升級機制**:

- 交易量累積自動升級（A）
- 付費會員制（C）
- 人工審核調整（B，不公開）

**擴充性**: 後續可調整等級數量、條件與費率（第四階段後擴充）

## 三、系統架構

### 3.1 技術選型

#### 前端技術

- **買家端**: Nuxt 3 (SSR/SSG) + PWA
  - 第二階段加入 Capacitor（預埋接口）
- **後台管理**: Vue 3 + Vite (SPA)
- **店面結帳**: Vue 3 PWA（手機/平板）

#### 後端技術

- **API 框架**: Fastify + TypeScript
- **資料庫**: PostgreSQL (Cloud SQL)
- **快取**: Redis Cloud（既有資源）
- **檔案儲存**: Google Cloud Storage (GCS)

#### 部署環境

- **前後端**: GCP Cloud Run (min-instances=0)
- **資料庫**: Cloud SQL for PostgreSQL (開發期關機)
- **CI/CD**: GitHub Actions

#### 第三方服務

- **金流**: 綠界 ECPay（信用卡 + LINE Pay）
- **物流**: 7-11 賣貨便、全家店到店
- **認證**: Google OAuth、Facebook Login（買家端）

## 四、功能需求

### 4.1 開發階段規劃

#### 第一階段：自營線上線下販售系統（MVP）

**核心功能**:

- ✅ 商品管理（卡片上架、編輯、下架）
- ✅ QR Code 生成與列印
- ✅ 實體店面掃碼結帳系統
- ✅ 線上商城（商品展示、直購、競標）
- ✅ 進貨管理（記錄進貨價格、供應商）
- ✅ 收入分析報表
- ✅ 基本賣家欄位（標記寄賣商品，統一抽成）

**商品資料結構**:

- UUID（唯一識別碼，每張卡獨立；周邊商品可共用）
- 基本資訊（類別、名稱、編號、系列）
- 鑑定狀態（裸卡 / PSA / ARS / BGS 等）
- 鑑定分數（選填）
- 進貨價格、售價
- 賣家（自營 / 第三方賣家）
- 上架狀態（待上架 / 已上架 / 已售出）
- 上架通路（僅線上 / 僅實體 / 線上線下同步）
- 圖片（最多 10 張：正面、背面必填；細節、鑑定書選填）
- 影片（選填，最多 1 個，限制 10 秒、5MB）
- 商品描述、狀況描述
- 進貨來源、供應商（選填）

**競標功能**（採用 eBay-like Proxy Bidding 代理出價機制，固定增額簡化版）:

- 賣家可設定：競標底價、每次加價金額、結束時間
- 可同時設定「直購價」和「競標」（混合模式）
- **代理出價**：買家輸入「最高願付金額」（maxBid），系統自動以最低必要金額代為出價
  - 顯示價（currentPrice）為目前最低勝出價，非出價者的 maxBid
  - maxBid 對其他用戶隱藏，僅出價者本人可見
  - 新出價進入時，系統自動跟價比較，以 incrementAmount 遞增至必要金額
  - 平手時先出價者優先
- 商品進入競標狀態時，後台會顯示通知（提醒店員下架實體展示）

**結帳流程**:

- 累加購物車模式（可掃多張卡後一次結帳）
- 支援現金、信用卡（預留接口）、LINE Pay
- 實體店面結帳後，商品立即標記已售出，線上自動下架

**金流串接**:

- 綠界 ECPay（信用卡 + LINE Pay）
- 實體信用卡機（預留接口）

#### 第二階段：買家會員系統

**功能**:

- 買家註冊登入（Google OAuth、Facebook Login）
- 購物車與訂單管理
- 紅利點數系統（購買累積點數，可折抵或兌換商品）
- 訂單追蹤（物流狀態、面交資訊）
- 會員等級（初期統一，預留後續升級制度）

**物流選項**:

- 7-11 賣貨便
- 全家店到店
- 實體店面面交（後台可設定面交地點與時間）
- 特定地點面交（可擴充）
- 黑貓宅配（第三階段預留）

#### 第三階段：賣家管理系統

**功能**:

- 賣家後台登入（獨立於買家系統）
- 寄賣申請與審核流程
- 賣家自行上架商品（需審核通過）
- 銷售報表（查看自己的銷售數據、抽成明細）
- 庫存管理（查看在庫商品）
- 退貨申請（賣家可申請取回未售出商品）

**賣家等級管理**:

- 自動升級（依交易量）
- 付費會員制
- 後台手動調整（不公開）

#### 第四階段：進階功能與優化

**功能**:

- 後台權限管理（超級管理員、商品管理員、財務管理員、店員）

## 五、詳細功能規格

### 5.1 商品管理

#### 5.1.1 商品分類

**唯一商品（一物一碼）**:

- 裸卡、鑑定卡
- 每張卡都有獨立 UUID
- 即使同款、同分數也是不同商品

**庫存商品（共用 SKU）**:

- 周邊商品（保護殼、保護套等）
- 同款共用一個 UUID
- 有庫存數量概念

#### 5.1.2 商品上架流程

**自營商品**:

1. 管理員在後台填寫商品資訊
2. 上傳圖片/影片（自動壓縮、浮水印、多尺寸）
3. 選擇上架通路（僅線上 / 僅實體 / 線上線下同步）
4. 生成 QR Code（UUID）
5. 列印 QR Code 貼紙（包含基本介紹、店家名稱）
6. 自由上架，無需審核

**寄賣商品**:

1. 賣家寄送實體卡片到店面
2. 店家收到後審核（檢查品質、拍照）
3. 管理員在後台上架（可選擇賣家是誰）
4. 賣家在後台可查看自己的商品狀態
5. 審核通過後上架

#### 5.1.3 圖片與影片處理

**圖片規格**:

- 必填：正面、背面
- 選填：細節圖、鑑定證書
- 最多 10 張（無影片時）
- 最多 3 張（有影片時）

**自動處理**:

```
原圖上傳 → GCS
  ↓
自動生成：
├─ 縮圖（200x200，列表頁）
├─ 中圖（800x800，詳情頁，WebP + 浮水印）
├─ 大圖（1200x1200，放大檢視，WebP + 浮水印）
└─ 原圖備份
```

**影片規格**:

- 限制 10 秒內
- 自動壓縮成 720p, H.264
- 限制檔案 5MB 以內
- 若有影片，圖片限制 3 張

**成本優化**:

- Lazy Load（延遲載入）
- WebP 格式（比 JPG 小 30%）
- 90 天後自動轉 GCS 冷儲存

#### 5.2.1 QR Code 設計

**內容**:

- UUID（商品唯一識別碼）
- 可選：商品名稱、價格（方便肉眼識別）

**貼紙設計**:

1. 店員使用手機/平板開啟結帳系統（Vue 3 PWA）
2. 掃描卡片 QR Code（相機 or 掃碼槍）
3. 商品加入購物車（累加模式）
4. 客人可繼續挑選或結帳
5. 選擇付款方式（現金 / LINE Pay / 信用卡）
6. 確認付款後，系統自動：
   - 標記商品為「已售出」
   - 線上商城同步下架
   - 產生訂單記錄

**支援混合模式**:

- 可累加多張卡後一次結帳
- 也可單張即時結帳

### 5.3 線上商城（買家端）

#### 5.3.1 商品瀏覽

- 分類篩選（海賊王、寶可夢、遊戲王等）
- 狀態篩選（裸卡、鑑定卡、周邊）
- 價格排序
- 競標中商品特別標示

#### 5.3.2 商品詳情頁

- 圖片輪播（支援放大檢視）
- 影片播放（若有）
- 商品描述、狀況描述
- 鑑定資訊（若為鑑定卡）
- 購買選項：
  - 直購按鈕（若有直購價）
  - 競標出價（若開放競標）
  - 面交選項

#### 5.3.3 競標功能（Proxy Bidding 代理出價）

**拍賣設定**（賣家設定）:

- 競標底價（startingPrice）
- 每次加價金額（incrementAmount）
- 結束時間
- 可選：直購價（Buy It Now）

**代理出價機制**（參考 eBay，MVP 採固定增額而非 eBay 分段加價梯度）:

- 買家輸入「最高願付金額」（maxBid），而非直接出價金額
- 系統自動用最低必要金額代為競標：
  1. 首位出價者 → 顯示價 = 底標價（不暴露 maxBid）
  2. 新出價者進入 → 系統比較雙方 maxBid，自動跟價至必要金額
  3. maxBid 較高者勝出，顯示價 = 敗方 maxBid + 加價金額
  4. 平手時先出價者優先
- maxBid 對其他用戶隱藏，僅出價者本人可見
- 同一用戶可追加 maxBid（僅允許加碼，不可降低）

**拍賣流程**:

1. 買家設定最高出價（maxBid ≥ currentPrice + incrementAmount）
2. 系統自動跟價計算，更新顯示價（currentPrice）
3. WebSocket 即時推送新顯示價給所有訂閱者
4. 出價紀錄顯示（僅顯示觸發後的顯示價，不顯示 maxBid）
5. 競標倒數計時
6. 結束時，最高 proxy 持有者得標
7. 系統發送得標通知

**實時通知**:

- 當商品進入競標狀態（有人出價），後台顯示通知
- 提醒店員將該卡片從實體展示架下架
- 避免實體店面同時售出

**直購優先**（若設定直購價）:

- 買家可選擇直接以直購價購買
- 無論當前競標價多少，直購立即成交
- 商品下架，競標結束

#### 5.3.4 購物車與結帳

**購物車**:

- 支援多件商品
- 實時庫存檢查（避免已售出）
- 競標中商品無法加入購物車

**結帳流程**:

1. 選擇配送方式：
   - 7-11 賣貨便
   - 全家店到店
   - 實體店面面交
   - 特定地點面交
2. 選擇付款方式：
   - 信用卡（綠界）
   - LINE Pay（綠界）
   - 轉帳（人工確認）
   - 面交現金
3. 使用紅利點數折抵（選填）
4. 確認訂單，完成付款

## 六、非功能性需求

### 6.1 效能需求

- **頁面載入時間**: 首頁 < 2 秒（3G 網路）
- **API 回應時間**: 95% 請求 < 500ms
- **圖片載入**: Lazy Load，優先載入可視區域
- **並發處理**: 支援至少 100 併發用戶（初期）

### 6.2 安全性需求

- **資料傳輸**: 全站 HTTPS
- **認證**: JWT (後台) / OAuth (前台)
- **密碼**: Bcrypt 加密
- **SQL Injection**: 使用 ORM/參數化查詢
- **XSS 防護**: 輸入驗證、輸出編碼
- **CSRF 防護**: Token 驗證
- **金流安全**: 遵循 PCI DSS 規範（使用第三方金流）

### 6.3 可用性需求

- **正常運行時間**: 99.5% (SLA)

## 七、使用者流程

### 7.1 買家購買流程（線上）

```
註冊/登入 (OAuth)
  ↓
瀏覽商品（分類、篩選）
  ↓
查看商品詳情
  ↓
選擇購買方式：
├─ 直購 → 加入購物車 → 結帳
└─ 競標 → 出價 → 等待結束 → 得標 → 結帳
  ↓
選擇配送方式（超商 / 面交）
  ↓
選擇付款方式（信用卡 / LINE Pay / 轉帳）
  ↓
使用紅利點數（選填）
  ↓
完成付款
  ↓
等待出貨 / 面交
  ↓
收到商品 → 獲得紅利點數
```

### 7.2 實體店面購買流程

```
客人到店面挑選卡片
  ↓
店員掃描 QR Code（累加購物車）
  ↓
客人繼續挑選 or 結帳
  ↓
選擇付款方式（現金 / LINE Pay / 信用卡）
  ↓
完成付款
  ↓
系統自動：
├─ 標記商品已售出
└─ 線上商城同步下架
```

### 7.3 賣家寄賣流程（第三階段）

```
賣家註冊/審核（管理員建立帳號）
  ↓
寄送卡片到店面
  ↓
店家收到，審核檢查
  ↓
管理員在後台上架（或賣家自行上架 → 待審核）
  ↓
審核通過 → 上架展示（線上 + 實體）
  ↓
商品售出
  ↓
系統自動計算抽成
  ↓
收益進入賣家虛擬錢包
  ↓
每月結算，賣家申請提領
  ↓
人工匯款
```

## 九、風險與應對

### 9.1 技術風險

| 風險                | 影響 | 應對策略                                                                    |
| ------------------- | ---- | --------------------------------------------------------------------------- |
| Cloud SQL 成本超支  | 高   | 使用 min-instances=0，監控用量，設定預算警報                                |
| 競標系統並發問題    | 中   | 使用 Redis 分散式鎖 + Prisma $transaction，Proxy Bidding 跟價在鎖內原子完成 |
| 圖片儲存成本過高    | 中   | WebP 壓縮、生命週期管理、90 天後轉冷儲存                                    |
| 第三方金流 API 變動 | 中   | Adapter Pattern 封裝，易於替換                                              |

### 9.2 商業風險

| 風險           | 影響 | 應對策略                                 |
| -------------- | ---- | ---------------------------------------- |
| 初期賣家數不足 | 高   | 第一階段以自營為主，建立口碑後再推廣寄賣 |
| 假卡問題       | 高   | 寄賣商品統一由店家審核檢查               |
| 競標流標率高   | 中   | 提供「直購 + 競標」混合模式，提高成交率  |
| 物流糾紛       | 中   | 明確物流責任，高價商品建議面交或保險     |
